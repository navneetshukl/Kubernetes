# Notification System

A Kubernetes-based notification system consisting of an API server, worker, sidecar, and migration components.

## Overview

This project implements a notification pipeline with the following components:
- **API Server** (`notification-api`) - RESTful API for creating and retrieving notifications
- **Worker** (`notification-worker`) - Processes notifications asynchronously
- **Sidecar** (`notification-sidecar`) - Monitors logs and handles sidecar operations
- **Migration** (`notification-migration`) - Database migration component
- **PostgreSQL** - Primary database for storing notifications

## Features

### 1. Notification API
- RESTful endpoints for creating (`POST /notifications`) and retrieving (`GET /notifications`) notifications
- Database integration with PostgreSQL for persistent storage
- Input validation using Go validation tags
- Sets initial notification status to "pending"
- Connection retry logic with exponential backoff

### 2. Notification Worker
- Async processing of notifications
- Polling mechanism to fetch pending notifications from the API
- Logs state transitions (pending → processing → completed)
- Logging of processing steps
- Periodic polling with configurable intervals

### 3. Notification Sidecar
- Log monitoring - tails log files for sidecar operations
- File-based logging with timestamped entries
- Continuous polling of log files for new entries

### 4. Database Layer
- PostgreSQL configuration with SSL support
- Notifications table with fields: id, user_id, message, status, created_at
- Connection pooling and retry logic for database operations
- Table verification during startup

### 5. Database Migration
- Schema migration to create the notifications table
- Initial table creation with proper constraints
- Verification of table existence after migration

### 6. Infrastructure
- PersistentVolume for PostgreSQL data storage
- PersistentVolumeClaim for dynamic provisioning
- Kubernetes Deployments for all services
- Service for internal communication (notification-api-service)
- ClusterIP for the API service

## Component Details

### Notification API

The API server provides two main endpoints:
- `POST /notifications` - Creates a notification with status "pending"
- `GET /notifications` - Retrieves all notifications

Key features:
- Uses Gin framework for HTTP handling
- Implements database connection with retry logic
- Validates incoming JSON payloads
- Returns appropriate HTTP status codes

### Notification Worker

The worker component processes notifications asynchronously:
- Polls the API for pending notifications
- Logs state transitions from pending to processing to completed
- Runs continuously with configurable polling intervals

### Notification Sidecar

The sidecar monitors log files generated by the worker and API components, providing observability into the system's operational state.

### Database Migration

A dedicated migration component that initializes the PostgreSQL database by creating the notifications table. This ensures the database schema is properly set up before deployment.

### PostgreSQL Configuration

The system uses PostgreSQL with the following configuration:
- Host: `postgres-service`
- Port: `5433`
- User: `postgres`
- Password: `postgres`
- Database: `notifications`
- SSL Mode: `disable`

## Quick Start

```bash
# Build all Docker images
make build

# Deploy to Kubernetes
make deploy

# Or use individual targets
make build-api      # Build API image
make build-worker   # Build worker image
make build-sidecar  # Build sidecar image
make build-migration # Build migration image

# Load images into minikube
make load

# Run the API server locally
make build-api
```

## Running the Components

### API Server
- Built with Gin framework
- Exposes `/notifications` endpoint
- Connects to PostgreSQL via ConfigMap
- Runs on port 8080

### Worker
- Built with Go
- Polls API for pending notifications
- Processes each notification
- Runs continuously with configurable polling interval

### Sidecar
- Built with Go
- Monitors log files
- Provides log aggregation

### Migration
- Dedicated initialization container
- Creates notifications table in PostgreSQL
- Runs as an init container in the API deployment

## Configuration

Environment variables used throughout the project:
- `DB_HOST` - PostgreSQL host
- `DB_PORT` - PostgreSQL port
- `DB_USER` - Database username
- `DB_PASSWORD` - Database password
- `DB_NAME` - Database name (notifications)
- `DB_SSLMODE` - SSL mode (disable)
- `API_URL` - API service URL for the worker
- `POLL_INTERVAL` - Worker polling interval
